# Mindframe — LLM-in-the-loop Infra Dashboard

Generalized framework for monitoring any infrastructure by letting Claude write the probes. Ships as a Claude plugin. Successor-in-spirit to taskboard (`../../tools/taskboard/`), which stays running on :42069 and will eventually become a mindframe deployment.

## The Idea

Users declare systems and components in a config file. The framework probes each component for live status via **source packs**. Claude generates packs on demand, grounded in **fixtures** — real API responses captured from the user's actual stack. The maintainer ships a few reference packs + built-in primitives; Claude writes the rest.

## How a user's dashboard looks

```python
# <project>/dashboard.py
from mindframe import serve
from mindframe.packs.github import pack as gh_pack
import my_company.packs.stripe as stripe_pack  # generated by Claude

app = serve(
    systems_path="systems.json",
    packs={"gh": gh_pack, "stripe": stripe_pack},
    poll_interval=30,
)
```

`serve()` returns a FastAPI app. Run under uvicorn. User writes a `systems.json` describing systems, components, kinds, refs, thresholds. Framework polls, derives state, exposes JSON + HTML. User never writes server plumbing — the framework is the runtime.

## Core Design

### Fixtures are the contract

A pack is valid iff its `probe()` produces a well-formed `Status` against every fixture in `fixtures/`. No fixtures, no pack. Fixtures are real API responses captured from live systems, stored raw. See `mindframe/fixtures.py` for the capture helper.

### Probe reports facts, framework derives state

`probe()` returns `Status{facts, details, checked_at}` — no `state` field. `facts` are thresholdable numbers/booleans/enums. The framework applies user-configured thresholds (from `systems.json`) to derive `healthy | warn | crit | error`.

Why: "0 open PRs" is healthy for a dead repo, degraded for a critical service. State depends on user intent, not on the data.

Threshold DSL (per-fact, in `systems.json`):

    warn_gt / crit_gt / warn_lt / crit_lt          numeric
    warn_eq / crit_eq                              exact match
    warn_if / crit_if                              boolean
    warn_if_in / crit_if_in                        enum
    warn_if_not_in / crit_if_not_in                enum

Full logic in `mindframe/thresholds.py`. Probe-level errors always resolve to `error` state.

### One required method, rest lazy-materialized

`probe(kind, ref, ctx) -> Status` is the only required method. `list_candidates`, `detect`, etc. are optional — the framework asks Claude to regenerate the pack with them when the UX needs them.

### One pack, many kinds

Each pack declares its own `KINDS`, `REF_SCHEMAS`, `SCRUB`. The framework treats kinds as opaque namespaced strings (`gh/repo`, `k8s/deployment`, `systemd/unit`). Kind-prefix before the slash is the packs-dict key.

### Built-in primitives ship with the core

Four live-only probes are registered by default — `http`, `tcp`, `cmd`, `file`. They don't need fixtures (input *is* the ref) and cover the long tail of "ping this URL" / "is this port open" without forcing pack generation. See `mindframe/probes/`.

## Structure

```
mindframe/
├── __init__.py          # exports: serve, Status, Context, derive_state, BUILTIN_PACKS
├── contract.py          # Status, Source protocol, Context
├── serve.py             # FastAPI factory — the runtime
├── thresholds.py        # facts + rules → healthy|warn|crit
├── fixtures.py          # capture helper
├── probes/              # built-in primitives (http, tcp, cmd, file)
└── packs/               # reference source packs (github)
    └── <platform>/
        ├── pack.py      # probe() implementation
        └── fixtures/    # captured API responses
examples/
└── minimal/             # smallest runnable dashboard (primitives only)
tests/                   # validate runtime, primitives, thresholds, each pack
docs/contract.md         # design decisions + findings
```

## systems.json shape

```json
{
  "systems": {
    "beats": {
      "description": "Infinite lofi radio",
      "url": "https://beats.softwaresoftware.dev",
      "components": {
        "repo": {
          "kind": "gh/repo",
          "ref":  "softwaresoftware-dev/beats",
          "thresholds": {
            "pushed_days_ago": {"warn_gt": 30, "crit_gt": 90},
            "archived":        {"crit_if": true}
          }
        },
        "site": {
          "kind": "http",
          "ref":  "https://beats.softwaresoftware.dev",
          "thresholds": {"status_code": {"crit_if_not_in": [200]}}
        }
      }
    }
  }
}
```
